# Remote Config гри: окремі параметри — `shared`, `android`, `ios` (+ старий `config`)

Власник 31.10.2026: «правило про ремоут конфіг і тікток — у репозиторій студії… тікток зараз тільки для Android, а вийде iOS — там теж має
бути TikTok SDK… коли вийде iOS, я дам ід і секрет — допишеш у ремоут конфіг». Того ж дня: «ремоут конфіг треба гарно структурувати… блок,
що саме для Android, що саме для iOS і що спільне, і тоді ясно, що кому… чи, може, 2 окремі ремоут конфіги — це треба якісно вирішити».
Для всіх ігор студії (Orbit Dash, CubePix, наступні). Еталон — Orbit Dash, патч 289.

## Рішення: один проєкт Firebase, окремий параметр на кожну аудиторію

| параметр | для кого | що всередині |
|---|---|---|
| `shared` | обидві платформи | `live` — вікна сезонів |
| `android` | лише Android | `tiktok` — ключі TikTok Android |
| `ios` | лише iPhone | `tiktok` — ключі TikTok iOS; `update` — остання версія в App Store |
| `config` | **старе** — лише вже випущені збірки | копія того, що вони читають (Orbit Dash: `tiktok` + `live` для Android ≤ 2.3.0) |

```json
shared   { "live": { "halloween": { "on": true, "from": "2026-10-29", "to": "2026-11-30" } } }
android  { "tiktok": { "app_id": "<TikTok App ID Android>[,<ще один>]", "secret": "<App secret Android>" } }
ios      { "tiktok": { "app_id": "<TikTok App ID iOS>", "secret": "<App secret iOS>" },
           "update": { "latest": "", "app_id": "<Apple ID гри в App Store>" } }
config   { "tiktok": { …копія android.tiktok… }, "live": { …копія shared.live… } }
```

**Чому окремі параметри, а не один великий JSON і не два проєкти Firebase:**
- у консолі Firebase видно, що кому: окремий рядок з описом на кожну аудиторію;
- кома не там в `ios` не ламає Android і сезони — кожен параметр розбирається окремо;
- кожен параметр має свою історію версій; пізніше на один параметр можна навісити умову (країна, версія, % гравців), не чіпаючи решти;
- **два проєкти Firebase — ні:** Analytics, Crashlytics, FCM, App Check і RANKS живуть в одному проєкті; розділення розірве статистику й
  подвоїть роботу;
- одна платформа отримує й параметр іншої (Remote Config віддає всі параметри). Секрет TikTok — ключ, який і так вшито в застосунок, тож це
  не страшно. Якщо колись треба суворо — на параметр `ios` / `android` ставиться умова «лише застосунок цієї платформи», без зміни коду гри.

## Поля

- **`tiktok`** — TikTok Business SDK (Events Manager): `app_id` (кілька — через кому) і `secret`, **лише рядки** (19-значний App ID числом
  JSON спотворюється). Порожньо / немає — SDK на цій платформі не стартує, тихо. Стартує **лише зі згодою** гравця. Як саме — `tiktok.md`.
- **`live`** — вікна сезонів (`on`, `from`, `to` — місцева дата гравця, включно); вшиті дати в грі — запас без мережі; `on: false` — вимикач.
- **`update`** — оновлення на iPhone (`docs/ux/ios-updates.md`): `latest` пише Claude лише після «вже в App Store» від власника; `app_id` — Apple ID.

## Як читає гра

- Кожна платформа читає **`shared` + свій параметр**. Кожен блок береться з нового параметра (об'єктом, навіть порожнім — це рішення
  власника); немає там, параметр порожній чи зламаний — зі **старого місця** в `config`. Тож нова збірка працює і на старому конфігу, і на
  новому, і на половинчастому.
- Старе місце для TikTok — лише на Android: верхній `config.tiktok` — це ключі Android, iPhone його не бере ніколи.
- Тести парсера — на одній фікстурі з усіма розкладками: лише старе, розкладене, нове перекриває старе, половинчасте, порожні й зламані
  значення; плюс тест «як читають випущені збірки» (їм нові параметри невидимі — живуть на копії в `config`).

## Порядок переходу (кожна гра окремо)

1. Оновлення гри, що читає параметри, — у магазини (Android і iOS).
2. Коли воно вийшло — **`migrate`** інструментом гри (Orbit Dash: `docs/lab/analytics/rc.py migrate --dry`, потім без `--dry`):
   `live` → `shared`, `tiktok` → `android`, `ios` → `ios.update`, порожнє `ios.tiktok` — місце під ключі iPhone; `config` лишається копією
   для старих збірок. **Лише з «так» власника.**
3. Далі всі записи — у нові параметри; копію в `config` інструмент оновлює сам. `config` — геть, коли старих версій практично не лишилось
   (Play Console / App Store Connect: частка версій) — теж з «так» власника.

## Хто що пише

- **Секрети (TikTok) — ніколи в git, логи чи чат-підсумки.** Найкраще — власник сам запускає інструмент (`! python3 … rc.py tiktok ios <App ID>`)
  і вводить секрет у прихований запит; або дає Claude — тоді в чаті лише App ID і довжина секрету. Інструмент маскує секрети у виводі,
  секрет — не аргументом командного рядка (історія shell), пише лише свій блок, решту — байт у байт.
- Будь-який запис у бойовий Remote Config — лише з «так» власника; спершу `--dry` (Firebase validateOnly — нічого не публікується) і
  показати, що зміниться (секрети — маскою).
- Новий блок — спершу в цьому правилі й у коді гри (невідомі поля гра ігнорує), потім у Remote Config. Старий `config` руками не правимо.

## У грі (libGDX, Android + iOS) — як в Orbit Dash

- `:core` — `services/remote/RemoteLive.publish(shared, platform, legacy)` і `RemoteBlocks` (з якого параметра кожен блок), ключі TikTok —
  `services/tiktok/TikTokRules`.
- Android — Firebase Remote Config SDK: `getString("shared")`, `getString("android")`, `getString("config")`.
- iOS — REST `firebase:fetch` без SDK (`IOSRemoteConfig`): відповідь несе всі параметри — беремо `shared`, `ios`, `config`, зберігаємо на
  пристрої під їхніми іменами.
- **TikTok — як саме, однаково в усіх іграх (ключі, події, згода, debug, SDK iOS, перевірка, промпт для сесії гри) — `tiktok.md`** поруч.
