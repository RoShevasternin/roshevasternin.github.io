# GitHub Actions — економно: що можна зробити на Маці, робимо на Маці

Рішення власника 08.11.2026 (Orbit Dash і CubePix: «що можеш зробити сам — роби сам, щоб економити GitHub Actions… щоб вистачало місячного безкоштовного ліміту»).
**Стандарт для всіх ігор студії.** Вставити в `CLAUDE.md` гри або дати сесії першим повідомленням.

**Навіщо.** У приватних репо безкоштовно лише 2 000 хвилин на місяць на весь акаунт: усі ігри ділять один ліміт. За 1–7.11.2026 Orbit Dash з'їв 604 хв, із них 535 — автопублікація сайту (≈ 12 хв кожна, 11,5 хв — перевірка в Chrome). Такий темп вичерпав би ліміт ≈ 22–23 числа, і тоді зупинилось би те, що справді потребує Actions. Хвилини macOS-раннера рахуються ×10, Windows ×2.

## Правило

| що | де |
|---|---|
| Збірка й публікація сайту, тести, разові перевірки, скрипти, надсилання | **локально на Маці, у сесії.** Спершу повні тести, потім публікація |
| Те, що мусить працювати без Мака: розклад (ранковий звіт, push), ручний запуск | GitHub Actions |
| Важкі кроки (Chrome, Gradle, збірка застосунку) | у CI **не** запускати автоматично; лише вручну й коли інакше ніяк |
| macOS-раннер | лише якщо немає іншого шляху, і спершу сказати власнику, скільки це хвилин |

## Перш ніж додати workflow чи тригер

1. Порахувати хвилини на місяць: `хвилин за запуск × запусків на місяць × множник раннера`.
2. Тригер `push` — лише з вузькими `paths:` і лише для швидких кроків. Публікація сайту на кожне злиття — ні, лише `workflow_dispatch`.
3. Розклад — настільки рідко, наскільки це справді потрібно. Миттєве сповіщення краще робити з самого сервісу (наприклад, з воркера), а не частим cron.
4. Запуск, який зависає, з'їдає хвилини: завжди `timeout-minutes` на job; `concurrency` з `cancel-in-progress` там, де запуски дублюються.

## Стеження

- Claude дивиться витрату хвилин, коли чіпає CI, і наприкінці великих робіт: `gh api /users/<власник>/settings/billing/usage` або Settings → Billing у браузері.
- Понад 1 000 хв до 15 числа — сказати власнику і знайти, що їсть хвилини. Понад 1 600 хв за місяць — лишити лише розклад, усе інше робити локально.

## Промпт для `CLAUDE.md` гри

```markdown
## GitHub Actions економно (рішення власника 08.11.2026, правило студії docs/process/github-actions.md)

Що Claude може зробити сам на Маці (збірка й публікація сайту, тести, перевірки, надсилання) — робить сам, не через GitHub Actions. Ліміт — 2 000 хв на місяць на всі ігри разом. Actions — лише для того, що мусить працювати без Мака: розклад і ручний запуск. Новий workflow чи тригер `push` — спершу порахувати хвилини на місяць; важкі кроки (Chrome, Gradle) у CI автоматично не запускати; на кожен job — `timeout-minutes`.
```

## Як зроблено

- **Orbit Dash:** сайт збирається й публікується локально (`site/build.py` → `site/publish.py`); `site.yml` і `policy.yml` — лише ручний запуск; у CI лишились розклад і `telegram.yml`. Правило — `Orbit Dash/docs/claude/memory/github-actions-economy.md`.
- **CubePix:** правило — `docs/claude/memory/github-actions-economy.md`; `.github/workflows/site.yml` переводиться на ручний запуск, публікація — локально.
