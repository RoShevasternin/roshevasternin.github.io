# Структура проєкту гри: `release/` і `market/` — однаково в усіх іграх студії

Власник 31.10.2026: «для мене по суті головне — це `release` і `market`: у релізі ключі, а в маркеті результати — відео, скріни, IPA, AAB,
усе необхідне для публікацій… щоб це було однаково й потім в інших проєктах». Зразок — CubePix (`Game CubePix PRIVATE/market/claude`),
так само Orbit Dash.

## `release/` — ключі (приватний git)

Усе, чим підписують і чим ходять до сервісів, — у `release/` **приватного** репозиторію гри, у git (щоб будь-яка сесія чи акаунт Claude
могли зібрати й підписати реліз):
- `release/android/` — keystore завантаження (`key<Гра>.jks`) і `meta data.txt` (alias і паролі);
- `release/ios/` — ключ App Store Connect / APNs (`AuthKey_*.p8`) і README, що це;
- `release/<сервіс>/` — інші ключі (напр. сервер RANKS, OAuth-клієнти) з README.

Правила: лише приватний репозиторій гри (у публічні — ніколи); у логи, чат і коміти інших репо значення не друкувати; новий ключ —
одразу сюди з рядком у README теки.

## `market/` — дві теки: власника і Claude

```
market/
  README.md          — що де (однаково в усіх іграх)
  results/           — ВЛАСНИКА: готове для публікацій
    README.md        — покажчик: тека · що · стан
    <дата>-<назва>/  — один результат: README «що це й куди вставити» + файли (AAB, IPA, скріни, відео, банери, тексти)
  claude/            — CLAUDE: робоча тека
    README.md
    tools/           — конвеєри, що роблять результати (код — у git; або в теках коду гри, як у CubePix)
    need/            — запас для відомої майбутньої роботи; README «навіщо й до коли»
```

- **`results/` — лише готове для власника.** Уміст — не в git (`.gitignore`: `market/results/*`, `!market/results/README.md`), бо все
  перезбирається інструментами. Великі файли не ростуть у git.
- **Використане — одразу геть.** Власник сказав «використав» або на питання Claude «ще треба?» відповів «ні» — Claude видаляє теку
  одразу й прибирає рядок із `results/README.md` (у git-історії лишається покажчик). «Про всяк випадок» не тримаємо.
- **Те, що потрібно Claude** (проміжне, заготовки, запас на конкретну дату — напр. картка магазину на 1 грудня), — у `claude/need/`
  з поясненням у README; минула причина — Claude прибирає сам.
- Нічого за межами проєкту (`~/Movies`, `~/Downloads` тощо).
- Чернетки конвеєрів (кадри, `out/`) — у своїх теках поза git, після результату — геть.

## Як застосувати в новій грі

Створити `release/` (з README кожної теки) і `market/{results,claude/{tools,need}}` з README як вище, рядки `.gitignore`, і рядок у
`CLAUDE.md` гри: «Структура `release/` і `market/` — правило студії `docs/process/project-layout.md` (roshevasternin.github.io)».
